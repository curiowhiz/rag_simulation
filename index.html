Stage 3 of 9

🧮 Vector Embeddings

Each chunk becomes a real TF-IDF vector: a classic lexical vector where a term's weight reflects how distinctive it is to that chunk. (This is not a neural embedding model. Those learn dense vectors from training data; TF-IDF is computed directly from your text, but it is a real, working vector representation with real cosine similarity.)

Stage 4 of 9

🗂️ Indexing & Storage

Every chunk's vector, text, and source metadata gets written into an index: what a vector database actually stores and searches over.

Stage 5 of 9

🔍 Retrieval

Ask a question. It is scored against every chunk in the index, then optionally filtered, blended with keyword search, and reranked.

Stage 6 of 9

🧩 Context Assembly / Prompt Construction

The retrieved chunks get assembled into the actual prompt a language model would receive: system instructions, numbered context, then the question.

Stage 7 of 9

✨ Generation

⚠ Simulated: no live LLM call

This demo runs fully client-side with no backend and no embedded API key, so this step assembles an extractive answer from the retrieved context instead of calling a real model. In production, the assembled prompt from Stage 6 would go straight to an LLM API (GPT, Claude, Gemini). Everything upstream of this step works exactly as shown.

Stage 8 of 9

🛡️ Output & Guardrails

Before an answer ships, production systems run checks like these: groundedness, confidence, and basic content safety.

Stage 9 of 9

📊 Observability & Feedback Loop

Every stage above is timed, a rough proxy for what a real trace would show. Feedback closes the loop and is what production systems use to catch regressions.
